Ingestion Flow

From uploading a PDF/DOCX to searchable vectors in Pinecone

The flow

LLM callMongoDB / PineconeOther tool or service
┌─ 1. USER uploads file (Streamlit)
│      POST /documents  (PDF or DOCX)
│
├─ 2. VALIDATE (DocumentService)
│      - type is PDF or DOCX (extension + magic bytes)
│      - size max 25 MB, filename sanitized
│      - quota: 5 documents per user, 95 total
│
├─ 3. CREATE RECORD (MongoDB)
│      status = "processing", owned by the user
│      API returns document_id right away
│      ── everything below runs in the background ──
│      (UI polls GET /documents/{id} until ready/failed)
│
├─ 4. EXTRACT TEXT per page
│      PDF  → PyMuPDF, one text block per real page
│      DOCX → split into ~3000-char "pages"
│      clean text; reject scanned/empty files
│
├─ 5. CHUNK each page (RecursiveCharacterTextSplitter)
│      1000 chars per chunk, 150 overlap
│      every chunk keeps its page number
│      → see chunking-strategy.html
│
├─ 6. EMBED chunks (gemini-embedding-001, RETRIEVAL_DOCUMENT)
│      each chunk text → 768-number vector
│      pipeline works 100 chunks at a time; each is embedded
│      in batches of 50, 1 s pause, retry on rate limit
│
├─ 7. UPSERT (Pinecone)
│      namespace = document_id (one per document)
│      id = {document_id}#{chunk_index}
│      vector + metadata (document_id, page_number, chunk_index, text)
│
├─ 8. SUMMARY (LLM)
│      2-3 sentences from excerpts across the document
│      (if it fails → document still becomes ready, no summary)
│
└─ 9. MARK READY (MongoDB)
       save page_count, chunk_count, summary
       status = "ready" → green badge in the UI

If something fails

  • Validation fails: API rejects the upload right away, nothing is stored.
  • Scanned / empty / password-protected / corrupt file: document marked "failed" with a clear message.
  • Embedding or Pinecone fails after retries: partial vectors are deleted from Pinecone, document marked "failed".
  • Summary fails: ignored, document still becomes "ready".
The core idea: the file becomes page text, the page text becomes small overlapping chunks, each chunk becomes a vector, and the vectors are stored in Pinecone under the document's own namespace, ready for chat.

Code: backend/app/api/documents.py, backend/app/services/documents.py, backend/app/services/ingestion.py, embeddings.py, vectorstore.py. Settings: backend/app/config.py.
