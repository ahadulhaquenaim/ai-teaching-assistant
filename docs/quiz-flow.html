Quiz Flow

Two quiz types share the same start, then split: Multiple choice and Short answer

Shared start (both types)

┌─ 1. USER fills the form (Streamlit)
│      document, topic (optional), difficulty, number of questions,
│      question type → Multiple choice OR Short answer
│      POST /quizzes
│
├─ 2. CHECKS (QuizService + MongoDB)
│      - number of questions ≤ 10
│      - document belongs to this user (ownership lookup)
│      - document status is "ready"
│      ── LangGraph quiz graph starts ──
│
└─ 3. SELECT CONTENT
       topic given?
         yes → embed topic (gemini-embedding-001, RETRIEVAL_QUERY)
               → Pinecone top 12 chunks for that topic
         no  → pick 12 chunks spread evenly across the whole document
               (fetched by chunk_index, no embedding needed)
       no chunks at all → error "No content is available"

       ↓ split by question type ↓

Flow 1: Multiple choice (MCQ)

Generate

┌─ 4. GENERATE (LLM, structured output)
│      prompt = difficulty guide + MCQ rules + topic
│             + excerpts sorted by page [Page N] (max 14,000 chars)
│      MCQ rules for the LLM:
│        - EXACTLY 4 options
│        - correct_answer copied exactly from one option
│        - wrong options plausible but clearly wrong
│        - no "All of the above" / "None of the above"
│      each question: text, 4 options, correct_answer, explanation, source_page
│
├─ 5. VALIDATE
│      a) rule checks (plain Python, no LLM)
│         - question text + explanation present
│         - source_page is one of the given pages
│         - no duplicate questions
│         - exactly 4 non-empty, distinct options
│         - no "all/none of the above"
│         - correct_answer matches exactly one option
│           (bare letter "B" is mapped to option B's text)
│      b) support check (LLM, one call for all)
│         - is the correct answer really in the source page text?
│
├─ 6. ENOUGH VALID?
│      no  → back to step 4 for the missing ones only, max 2 retries
│      yes → continue
│
├─ 7. SHUFFLE OPTIONS
│      LLMs like to put the correct answer first; shuffle hides it
│
└─ 8. SAVE (MongoDB) and SHOW
       UI shows question + 4 radio options, answers hidden

Submit and score

┌─ 1. USER picks one option per question → POST /quizzes/{id}/submit
│
├─ 2. SCORE (plain Python, NO LLM)
│      chosen option == correct option (case/punctuation ignored)?
│        yes   → 1 point, "Correct"
│        no    → 0 points, "Incorrect. The correct answer is: …"
│        empty → 0 points, "No answer given. The correct answer is: …"
│
└─ 3. SAVE ATTEMPT (MongoDB) and SHOW
       score, percentage, correct answer, explanation

Flow 2: Short answer

Generate

┌─ 4. GENERATE (LLM, structured output)
│      prompt = difficulty guide + short-answer rules + topic
│             + excerpts sorted by page [Page N] (max 14,000 chars)
│      short-answer rules for the LLM:
│        - options = empty list
│        - correct_answer = a 1-3 sentence MODEL answer from the text
│      each question: text, model answer, explanation, source_page
│
├─ 5. VALIDATE
│      a) rule checks (plain Python, no LLM)
│         - question text + explanation present
│         - source_page is one of the given pages
│         - no duplicate questions
│         - model answer present
│      b) support check (LLM, one call for all)
│         - is the model answer really in the source page text?
│
├─ 6. ENOUGH VALID?
│      no  → back to step 4 for the missing ones only, max 2 retries
│      yes → continue
│
│   (no shuffle step: there are no options)
│
└─ 7. SAVE (MongoDB) and SHOW
       UI shows question + text box, model answer hidden

Submit and score

┌─ 1. USER types answers → POST /quizzes/{id}/submit
│
├─ 2. SCORE (LLM, ONE call grades all non-empty answers)
│      input per item: question + reference (model) answer + user answer
│      LLM returns per item:
│        - score 0 to 1 (meaning matters, not exact wording;
│          partial credit allowed)
│        - 1-2 sentences of feedback
│      score ≥ 0.7 → counted as correct
│      empty answer → 0, "No answer given" (not sent to LLM)
│      user answers are treated as data, not instructions
│
└─ 3. SAVE ATTEMPT (MongoDB) and SHOW
       score (can be partial, e.g. 3.6 / 5), percentage,
       model answer, explanation, LLM feedback

Free-tier LLM is slow and rate-limited, so generation can take 20-60 s.

If something fails

  • Support check fails: questions that passed the rule checks are kept.
  • No valid questions after all retries: error "Could not generate valid questions. Try another topic or difficulty."
  • Fewer valid than asked after retries: quiz is saved with the valid ones only.
  • LLM / Pinecone down or rate-limited: "temporarily unavailable", nothing saved.
  • Short-answer grading fails: "Answers could not be graded right now", attempt not saved, user can resubmit. (MCQ cannot fail here: no LLM.)
The core idea: both types pick chunks, let the LLM write questions with a source page, and throw out bad ones with rules + an LLM support check. MCQ is then shuffled and scored by exact match in Python. Short answer is scored by the LLM against a model answer, with partial credit and feedback.
