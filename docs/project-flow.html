If Mongo startup tasks fail, the server keeps running so /health can report degraded (503).

4. Upload & ingestion

Source: api/documents.py, services/documents.py, services/ingestion.py

4a. Upload request (synchronous part, returns 202)

Documents pagefile_uploader → POST /documents
→
validate_uploadsanitize filename, extension check, read with 25 MB cap, check magic bytes (%PDF- / zip with word/document.xml)
→
createquota: ≤5 per user, ≤95 total → insert doc with status processing
→
202 + idBackgroundTask queued with the bytes

4b. Background ingestion pipeline

ExtractPDF: pymupdf per page. DOCX: docx2txt, split into ~3000-char "pages". Runs in a thread.
→
Cleanre-join hyphenated words, collapse whitespace
→
ensure_has_textscanned PDF (<50 chars/page avg) → fail, no OCR
→
Chunk1000 chars, 150 overlap, split per page so each chunk = one page
Embed batch of 100Gemini, 768-dim
→
Upsert to Pineconenamespace = document_id, id = doc#chunkIndex
↻ per batch →
Summarize2-3 sentences from chunks spread across the doc; failure is non-fatal
→
mark_readypage_count, chunk_count, summary

4c. Status polling and failure

  • Frontend polls GET /documents/{id} every 3 s (st.fragment run_every) until ready or failed.
  • Any IngestionError (scanned, empty, corrupt, password-protected) stores a user-facing message. Unexpected errors store a generic message.
  • _fail() deletes already-upserted vectors, then mark_failed.
  • Uploaded bytes live in memory only; never written to disk.

4d. Delete

DELETE /documents/{id}: ownership check → refuse if still processing (409) → delete Pinecone namespace → delete_cascade in Mongo (document, chat sessions/messages, quizzes, attempts).

5. Chat (Q&A graph)

Source: api/chat.py, services/chat.py, graphs/qa_graph.py, prompts/qa.py

5a. Request flow

Chat pagechat_input + "Search the web" toggle
→
POST /chat/sessionsonly if no session yet (needs a ready doc)
→
POST /chat/sessions/{id}/messages
→
ChatService.send_messageowned session → document id from DB (never client) → last 8 messages → run graph
QAGraph.run
→
Persist user + assistant messagesonly after success, so a failed turn retries cleanly
→
Touch sessionfirst question becomes the title (≤60 chars)

5b. Q&A graph

rewrite_queryfollow-up → standalone question. Skipped (no LLM call) if no history.
→
retrieve_documentembed question, Pinecone top-5 in the doc's namespace
→
grade_documentsone LLM call keeps relevant chunk ids. On LLM error keep all.
route_after_grading
No relevant chunks and retries < 1→ rephrase_query (uses doc summary) → back to retrieve_document
Web toggle ON→ build_search_query → web_search → grade_web_results → generate_answer
Web toggle OFF→ generate_answer

5c. generate_answer

  • No chunks and no web: deterministic reply "This is not covered in the document." (no LLM call, never guesses).
  • Document only: chunks ordered by page, answer prompt asks for "(Page N)" citations. Sources = cited pages ∩ retrieved pages; if none parsed, all retrieved pages.
  • With web results: two-section answer (document first, then a labeled web section). Web sources = only the [W#] ids the answer cites.
  • Web status notice (limit reached / unavailable / no results) is appended in italics.

Cost note: one chat turn = 2-4 LLM calls (rewrite, grade, answer, plus rephrase or web steps). Gemini free tier is about 5 RPM, hence the OpenRouter fallback.

6. Web search

Source: services/web_search.py, db/repositories/web_search.py, prompts/web.py

build_search_queryLLM makes a short query from question + summary. If it shares no words with them, use the question.
→
Cache lookupsha256(backend|region|query), 24 h TTL
miss →
Daily limitatomic try_consume, 20/user/UTC day
→
DuckDuckGo (ddgs)thread + timeout, 2 attempts on ratelimit/timeout, refund on failure
→
Sanitizestrip control chars and < >, truncate 1200 chars, dedupe URLs
→
grade_web_resultsdrop <40 chars (heuristic), then LLM relevance

Statuses: not_requested, used, no_results, limit_reached, unavailable. The search service never raises; the graph degrades to a document-only answer with a notice.

Untrusted content: web text is placed only inside <untrusted_web_content> and the prompt tells the model to treat it as reference data, never instructions.

7b. Validation (two stages)

StageChecks
Deterministic (check_question)question length ≥ 8; source_page is one of the provided pages; explanation present; no duplicates; MCQ: exactly 4 distinct non-empty options, no "all/none of the above", correct answer matches exactly one option (bare letter A-D accepted); short answer: model answer present

Enough valid questions → done. Otherwise regenerate only the missing ones with rejection reasons fed back, up to quiz_max_retries = 2 extra rounds. No valid questions at all → QuizGenerationError.

After the graph, MCQ options are shuffled (LLMs tend to put the right answer first) and the quiz is saved.

8. LLM & retry layer

Source: services/llm.py, services/retry.py, services/embeddings.py

  • LLMService is the only module that knows Gemini / Groq / OpenRouter. Two methods: generate_text and generate_structured(schema).
  • Calls try the primary, then the fallback. Final failure maps to a typed error: LLMRateLimitError, LLMProviderError, LLMCapabilityError. API keys are never put in messages.
  • Routes turn these into 503 ServiceUnavailableError with a friendly message.
  • with_retry (tenacity): exponential backoff + jitter for 429, 5xx, timeouts. Used by embeddings, Pinecone and DuckDuckGo.
  • Gemini 3+ models get thinking_level="low" to keep latency down.
  • Embeddings are batched (50) with a 1 s pause between batches for free-tier limits.

13. Security rules

  • Ownership everywhere. Every repo/endpoint checks the user owns the document/session/quiz. get_current_user currently returns the fixed local-dev-user; enabling auth later only replaces that dependency.
  • Document id comes from the DB, never the client, before any Pinecone query. The vector store itself knows nothing about users.
  • Upload validation by extension and magic bytes; size capped while streaming; filename sanitized.
  • Web content untrusted: sanitized, delimited, and flagged in the prompt.
  • Secrets are SecretStr; log lines record error types and status only.
