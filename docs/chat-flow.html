Chat Flow

From the moment you press send to the answer on screen

The flow

LLM callMongoDB / PineconeOther tool or service
┌─ 1. USER sends question (Streamlit)
│      POST /chat/sessions/{id}/messages  (text + web-search toggle)
│
├─ 2. CHECKS (ChatService + MongoDB)
│      - session belongs to this user
│      - document_id read from the session (never from the client)
│      - document status is "ready"
│      - load last 8 messages + document summary
│
├─ 3. REWRITE (LLM)  ← skipped on the first question
│      "what about his last job?" → "What did he do at his last job?"
│
├─ 4. EMBED the question (gemini-embedding-001, RETRIEVAL_QUERY)
│      question text → 768-number vector
│
├─ 5. RETRIEVE (Pinecone)
│      cosine similarity, only in this document's namespace
│      → top 5 chunks (text + page number)
│
├─ 6. GRADE (LLM, structured output)
│      keeps only the chunks that really help
│      (if grading fails → keep all 5)
│
├─ 7. NOTHING RELEVANT?
│      LLM rephrases the question (using the summary as a hint)
│      → repeat steps 4-6, once only
│
├─ 8. WEB SEARCH (only if toggle is ON)
│      LLM builds query → DuckDuckGo (max 20/user/day)
│      → drop short results → LLM keeps relevant ones
│      web text is sanitized and marked untrusted
│
├─ 9. ANSWER (LLM)
│      prompt = rules + chunks sorted by page [Page N] + question
│      - answer only from excerpts, cite pages
│      - no relevant chunk at all → fixed "not covered in the document"
│      - with web results → document answer first, then labeled web part
│
├─ 10. BUILD SOURCES
│      cited pages (only pages really retrieved) + cited web links
│      no page cited → list all retrieved pages
│
├─ 11. SAVE (MongoDB)
│      user message + assistant message (with sources)
│      first question also sets the chat title
│
└─ 12. SHOW in the UI
       answer with page citations (and web links)

Follow-up question13 (rewrite, grade, answer)
Nothing found, retry2+2 (rephrase, grade)
Web search ONsame+2 (search query, web grade)

Gemini free tier is about 5 requests per minute, so a turn can take seconds to tens of seconds.

If something fails

  • Rewrite or grading fails: the system falls back to the original question or keeps all 5 chunks, and the chat continues.
  • Embedding, Pinecone, or the answer call fails after retries: the API returns "temporarily unavailable" and saves nothing, so you can resend cleanly.
The core idea: the question becomes a vector, Pinecone finds the nearest chunks, an LLM filters them, and another LLM writes an answer using only those chunks, with page citations.
